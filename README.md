# Рассчётно-пояснительная записка для Курсовой работы по предмету "Проектирование высоконагруженных систем"

## 1. Тема и целевая аудитория

Тип сервиса: Мессенджер с поддержкой мультимедийных коммуникаций (видеозвонки) и социальных функций (аналог WeChat).

Основной функционал MVP:
* Авторизация и профиль пользователя: Регистрация по номеру телефона, управление контактами.
* Поиск (Search): Полнотекстовый поиск по контактам, диалогам и истории сообщений.
* Обмен сообщениями (Messaging): Передача текстовых, голосовых сообщений и медиафайлов (фото/видео/файлы) в личных и групповых чатах.
* Уведомления (Push Notifications): Гарантированная доставка пуш-уведомлений о новых сообщениях, вызовах и реакциях.
* Аудио- и видеозвонки: Сигнализация, установление и проведение личных и групповых звонков.
* Моменты (Сторисы): Публикация фото/видео контента на ограниченное время (доступно для просмотра только контактам)
* Отправка реакций на моменты.

Ключевые продуктовые решения:
* Клиентское хранение истории чатов (сервер выступает только очередью доставки).
* Гибридная архитектура видеосвязи (Использование P2P-соединений (WebRTC) для звонков и переключение на медиасерверы (SFU) при групповых звонках или плохом качестве сети).
* Строгая приватность контента: "Моменты" и реакции к ним доступны исключительно списку контактов пользователя.

Ключевые функции, характеризующие сервис:
1. Отправка и получение сообщений (текст, медиа, голос) со статусами доставки/прочтения.
2. Поиск по чатам, сообщениям и контактам.
3. Совершение аудио- и видеозвонков.
4. Создание "Моментов" (сторисов), просмотр ленты контактов и отправка реакций.
5. Доставка push-уведомлений о событиях.

Целевая аудитория:
* MAU (Месячная аудитория): 1.43 млрд пользователей.
* DAU (Дневная аудитория): 1.1 млрд пользователей.
* Географическое распределение: Глобальное. [^1]

#### 2.1.3 Среднее количество действий пользователя в день

Действия совершают только активные пользователи (DAU = 1,5 млн).

| Тип действия (функция MVP) | Действий в день на 1 DAU | Основание |
| :--- | :--- | :--- |

### 2.2 Технические метрики

#### 2.2.1 Размер хранения по типам данных (в месяц)

Расчёт ведётся от среднего количества отправлений в сутки (~400 000, исходя из 123 млн в год) и числа событий на одну посылку.

| Тип данных | Количество, шт./мес | Объём, ГБ/мес | Средний размер, КБ |
| :--- | :--- | :--- | :--- |
| События трекинга (от сканеров/ТСД) | ~60 млн событий | ~300 ГБ | 5 КБ (JSON с координатами, временем, ID оператора) |
| Профили и адреса пользователей | ~1,5 млн обновлений | ~75 ГБ | 50 КБ |
| **Итого (сырые данные)** | — | **~375 ГБ/мес** | — |

С учётом индексов БД, реплик и журналов транзакций реальный требуемый объём дискового пространства — **~1,2–1,5 ТБ/мес**.

#### 2.2.2 Сетевой трафик

| Тип трафика | Направление | Суточный объём, ГБ/сутки | Пиковое потребление, Гбит/с |
| :--- | :--- | :--- | :--- |
| Ответы на запросы трекинга | Egress | ~13,5 ГБ | ~0,02 Гбит/с |
| Загрузка данных о ПВЗ на карте | Egress | ~75,0 ГБ | ~0,10 Гбит/с |
| Приём событий от сканеров/ТСД | Ingress | ~3,0 ГБ | ~0,05 Гбит/с |
| **Итого** | — | **~91,5 ГБ/сутки** | **~0,17 Гбит/с** |

Пиковая нагрузка взята с коэффициентом 5–10 от средней (пики в логистике: утренняя сортировка, вечерние проверки статусов пользователями).

#### 2.2.3 RPS по типам запросов (средний и пиковый)

Формула: `Средний RPS = (Действий в день на DAU × DAU) / 86 400`.  
Пиковый RPS = Средний RPS × Коэффициент пика. Для пользовательских запросов коэффициент 10; для складских событий — исходя из 58 000 событий в минуту (966 RPS).

| Тип запроса | Действий/день на DAU | Средний RPS | Пиковый RPS |
| :--- | :--- | :--- | :--- |
| Просмотр статуса посылки (трекинг) | 3,0 | 52 | 520 |
| Загрузка данных о ПВЗ на карте | 1,0 | 17 | 170 |
| Оформление нового отправления | 0,05 | 1 | 10 |
| Приём события от сканера/ТСД (системный) | — | ~23 | 966 |
| **ИТОГО** | — | **~93** | **~1 666** |
